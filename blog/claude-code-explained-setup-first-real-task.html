Claude Code Explained: Setup to Your First Real Task

What Claude Code is, what it costs, how to install it on Mac, Linux and Windows, and a real bug fixed and proven with a test.

By Amit Singh · Compiled Canvas

A test says one hundred rupees split three ways adds up to ninety-nine. One rupee just vanished. I typed one sentence, and an AI read my project, made a plan, asked my permission, fixed the bug and proved the fix with a test. This guide shows you how to set up the same tool and do it yourself.

It goes with the video Claude Code Explained: Setup to Your First Real Task on the Compiled Canvas YouTube channel.

What is Claude Code?

Claude Code is an AI coding assistant that works inside your project. It can read your files, edit them and run commands, like your tests. But it asks before it acts.

Why that matters: in a normal chat window, the AI only sees what you paste, so it is guessing about the rest of your code. Claude Code can open the rest. Think of a mechanic. Describing a strange noise over the phone is the chat window. Bringing the car into the garage is Claude Code: the mechanic can look under the bonnet, and still asks before replacing anything.

Where the analogy stops: a mechanic is an expert you trust. Claude Code can be confidently wrong, so you stay the one who approves the work.

Is Claude Code free?

No. According to Anthropic's setup docs, the free Claude plan does not include Claude Code. You need one of these:

  • A paid Claude plan: Pro, Max, Ultra, Team or Enterprise. If you are learning on your own, Pro is usually the simplest start.
  • A Claude Console account: pay-as-you-go API access with pre-paid credits.

Be careful with "Claude Code free unlimited" tricks. Never paste your login into anything that isn't from Anthropic.

Your computer needs macOS 13 or newer, Windows 10 version 1809 or newer, or a recent Linux such as Ubuntu 20.04, plus 4 GB of RAM and an internet connection.

Install on Mac or Linux

Open Terminal and paste this one line. curl downloads Anthropic's official install script and bash runs it. Only run install scripts like this from a source you trust; this one comes straight from Anthropic's docs.

curl -fsSL https://claude.ai/install.sh | bash

Prefer Homebrew? There is a cask:

brew install --cask claude-code

Install on Windows

Open PowerShell and paste this. No administrator rights are needed.

irm https://claude.ai/install.ps1 | iex

Or use WinGet:

winget install Anthropic.ClaudeCode

Tip: install Git for Windows too, so Claude Code can use a proper Bash shell. Without it, it falls back to PowerShell. Installing with npm instead? It needs Node.js 22 or newer, and never put sudo in front of it.

Check that it worked

Close and reopen your terminal, then run:

claude --version
claude doctor

The first prints a version number followed by "Claude Code". If anything looks wrong, claude doctor checks your install and settings without starting a session.

How it works: the agent loop

  1. You ask for something in plain English.
  2. It reads the files it thinks are relevant.
  3. It decides on a plan.
  4. Before it edits a file or runs a command, it asks you.
  5. It does the step and checks the result (for example, did the test pass?).
  6. It repeats until the job is done or it needs you.

That loop is what makes it an agent rather than a chatbot, and the permission step is where you stay in control.

Permission modes (Shift + Tab)

Press Shift + Tab to switch modes. Yours might start in auto mode, where Claude Code goes ahead with actions it judges safe. The others:

  • Manual: asks before it edits files or runs commands.
  • Accept edits: changes files without asking each time.
  • Plan: thinks and proposes a plan first, without changing anything.

As a beginner, use manual mode, and plan mode for anything bigger than a one-line fix. Reading each change is how you learn, and how you catch mistakes.

Your first real task: the bill splitter bug

Here is the tiny project from the video. It splits a bill between friends, in whole rupees.

# splitter.py
def split_bill(total: int, people: int) -> list[int]:
    """Return how much each person pays. The shares must add up to the total."""
    if people <= 0:
        raise ValueError("people must be at least 1")
    share = total // people
    return [share] * people
# test_splitter.py
import unittest

from splitter import split_bill


class SplitBillTest(unittest.TestCase):
    def test_even_split(self):
        self.assertEqual(split_bill(90, 3), [30, 30, 30])

    def test_shares_add_up_to_total(self):
        self.assertEqual(sum(split_bill(100, 3)), 100)

    def test_rejects_zero_people(self):
        with self.assertRaises(ValueError):
            split_bill(100, 0)


if __name__ == "__main__":
    unittest.main()

total // people divides and rounds down. A hundred split three ways gives 33 each, and 33 × 3 is 99. One rupee is lost, and python3 -m unittest reports AssertionError: 99 != 100.

In the project folder, type claude. The first time, it asks whether you trust the folder; say yes only for code you trust. Then type /init: it reads the project and writes CLAUDE.md, a short guide it reads at the start of every session. In the recording it even spotted the failing test and explained why.

Now press Shift + Tab until it says plan mode, and describe the problem. A good request has three parts: the problem, what done means, and a rule:

The test test_shares_add_up_to_total fails. Fix split_bill so the shares always add up to the total, without changing the tests. Then run the tests.

Claude Code proposed a plan, and after approval it made this change (the real diff from the session):

-    share = total // people
-    return [share] * people
+    share, remainder = divmod(total, people)
+    return [share + 1] * remainder + [share] * (people - remainder)

divmod gives the share and the leftover. The first person pays one rupee extra: 34, 33, 33, which is 100. It also updated CLAUDE.md, then ran the tests. Don't just take its word for it: check yourself. Only splitter.py and CLAUDE.md changed, the test file is untouched, and python3 -m unittest says OK.

Why the rule "don't change the tests"? Otherwise an AI could "fix" the bug by changing the test instead of the code.

Five commands to start with

  • /help lists everything.
  • /clear starts a fresh conversation.
  • /compact summarises a long conversation to free up space.
  • /usage shows your cost and plan limits.
  • /model switches the AI model.

And /exit leaves.

Four mistakes to avoid

  1. Vague requests. "Make it better" gets random changes. Say what's wrong and what done looks like.
  2. Accepting everything without reading it. You're still the developer.
  3. No safety net. Use Git and commit before a big change, so you can always undo.
  4. Thinking it's never wrong. It can misunderstand, and write code that looks right but isn't. Tests are your proof.

The trade-offs: it uses your plan's limits or API credits, and the files it reads are sent to Anthropic's models to be processed, so keep secrets out and don't share code you're not allowed to.

Recap

  • Claude Code works inside your project, reads and changes files, runs commands, and asks before it acts.
  • You need a paid plan or a Console account.
  • One line installs it; claude --version checks it.
  • Use manual mode, plan mode for bigger jobs, and read every change.

Sources: Anthropic's Claude Code documentation (setup, quickstart, commands), checked on 9 November 2026. Plans and features change, so check the docs before you rely on them.
