Structured Output JSON from LLMs + System Prompts Explained

Structured output from LLMs: system prompt vs user prompt, why JSON from an AI breaks, schemas, and a Python check that rejects bad replies.

1Your code crashes

You ask the AI for JSON, but get a paragraph, and your code crashes. Here's how to never lose a response again.

A chatbot answer is for a person. But your program needs fields it can read. Name, skills, years.

Today, the two tools that fix it. The system prompt, and structured output, plus a Python check so bad replies never reach your code.

"Sure! Here is the JSON you asked for…"json.loads → CRASHparagraph → personJSON → programSYSTEM PROMPTJSON OUTPUTPYTHON CHECK

2The system prompt

There's one message your users never see. And it controls everything the AI says.

Every chat has roles. The system message sets the rules. The user message is the question. The assistant message is the reply.

Think of a new employee. The system prompt is the job description they read on day one. The user prompt is each customer at the counter.

So put lasting rules in the system prompt. Who it is, the format, what it must never do. Put the actual task in the user message.

THE SYSTEMPROMPTsystem: the rulesuser: the questionassistant: the replysystem = job descriptionuser = each customer

3Why json breaks

Now, why does asking for JSON fail, even when you say please? Three ways, and you'll hit all three.

One. Chatty text around it. Sure, here you go. Your JSON parser chokes on the first word.

Two. Markdown fences. Three backticks and the word json, wrapped around the real data.

Three. The wrong shape. Years comes back as the word two instead of the number two. It parses, but your maths breaks.

"Sure! { … }"```json { … } ```"years": "two"

4Structured output

Here's the real fix, and most big model APIs have it now. Structured output.

Instead of asking nicely, you send a schema. A description of every field and its type.

The API then makes the model fill that shape. It's like giving someone a form with boxes, instead of a blank page.

Each provider names it differently. JSON mode, response format, tools. Check your provider's docs. The idea is the same everywhere.

name: stringskills: list of stringsyears: integerJSON moderesponse formattools

5Check it in Python

Edit the code and press Run to try it right here, or copy it and run python3 structured_output.py.

structured_output.py · click to editDownload
# Lesson 8: system prompts and structured (JSON) output, checked before your code trusts it.
import json

# What you send: a system prompt with the rules, and the user's message
messages = [
    {"role": "system", "content": "You extract job candidates. Reply ONLY with JSON: "
                                  '{"name": string, "skills": [string], "years": integer}'},
    {"role": "user", "content": "Asha has 2 years of experience with Java and SQL."},
]

# What a model often sends back: JSON wrapped in a markdown fence
reply = '```json\n{"name": "Asha", "skills": ["Java", "SQL"], "years": 2}\n```'

SCHEMA = {"name": str, "skills": list, "years": int}

def parse(reply: str) -> dict:
    text = reply.strip().removeprefix("```json").removesuffix("```").strip()
    data = json.loads(text)                      # fails loudly if it isn't JSON
    for key, kind in SCHEMA.items():             # check every field and its type
        if not isinstance(data.get(key), kind):
            raise ValueError(f"field '{key}' is missing or not {kind.__name__}")
    return data

candidate = parse(reply)
print(candidate["name"], candidate["skills"], candidate["years"])

for bad in ['Sure! Here is the JSON you asked for.', '{"name": "Ravi", "years": "two"}']:
    try:
        parse(bad)
    except (json.JSONDecodeError, ValueError) as e:
        print("rejected:", type(e).__name__)
▶ Output
parse(reply) → {'name': 'Asha', 'skills': ['Java', 'SQL'], 'years': 2}
parse('Sure! Here is...') → JSONDecodeError

Even with structured output, never trust a reply blindly. Here's a check in Python. The schema says which fields we need.

Strip any code fences, then parse. If it isn't JSON at all, json loads fails loudly, which is what we want.

Then check every field and its type. A wrong type raises an error before it reaches the rest of your program.

6Mistakes to avoid

Four mistakes I see in almost every first AI project. Number four is the dangerous one.

One. Rules in the user message. They get pushed out of a long chat. Put lasting rules in the system prompt.

Two. No example. Show one filled-in JSON object in the prompt. That's few-shot, from the last lesson.

Three. No retry. If parsing fails, send the error back and ask again, once or twice.

Four. Trusting the values. Valid JSON can still hold wrong facts. Check the important ones.

7Cheat sheet

  • System = lasting rules
  • User = this task
  • Words · fences · types
  • Send a schema
  • Check in code
  • Retry on failure

8Quick quiz

1. Which message sets rules for the whole conversation?

2. What do you send to make the model fill a fixed shape?

A schema.

3. Years comes back as the text two. What should your code do?

Reject it, and ask again.
