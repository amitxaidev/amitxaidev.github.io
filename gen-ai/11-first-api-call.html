110 lines of Python

You can build your own ChatGPT in ten lines of Python. But most tutorials skip the part that makes it feel fast. Here's how.

Today you'll send a real message to a real model, read the reply, and then stream it word by word, the way chat apps do.

You'll need the setup from the last lesson. A virtual environment, the library, and your key in dot env.

2What a call sends

First, what actually travels to the model. Once you see this, every AI library makes sense.

Your program sends a request over the internet. It carries your key, the model's name, the messages, and some settings.

The provider runs the model and sends back a response. The text, plus how many tokens you used.

Like ordering food on an app. You send the order with your account. The kitchen sends back the food, and the bill.

keymodelmessagessettingsthe reply texttokens in / outorder + account → kitchenfood + bill → you

3The 3 roles

Every chatbot conversation, from any company, is built from just three roles.

System sets the rules. You're a friendly Java tutor. Answer in two sentences.

User is the person asking. What is a HashMap?

Assistant is the model's reply. To continue a chat, you send the earlier user and assistant messages back each time. The model doesn't remember on its own.

4Your first call

Edit the code and press Run to try it right here, or copy it and run python3 first_call.py.

first_call.py · click to editDownload
# Lesson 11: your first LLM API call, then the same call streamed word by word.
# Needs the setup from lesson 10: pip install anthropic python-dotenv, and ANTHROPIC_API_KEY in .env
from dotenv import load_dotenv
import anthropic

load_dotenv()
client = anthropic.Anthropic()                  # reads ANTHROPIC_API_KEY from the environment
MODEL = "claude-haiku-5-5"                      # a small, fast model

reply = client.messages.create(
    model=MODEL,
    max_tokens=200,                             # upper limit on the answer's length
    temperature=0.3,                            # low = focused, high = creative
    system="You are a friendly Java tutor. Answer in two short sentences.",
    messages=[{"role": "user", "content": "What is a HashMap?"}],
)
print(reply.content[0].text)
print("tokens in/out:", reply.usage.input_tokens, reply.usage.output_tokens)

print("\nStreaming:")
with client.messages.stream(
    model=MODEL,
    max_tokens=200,
    messages=[{"role": "user", "content": "Explain recursion in one line."}],
) as stream:
    for text in stream.text_stream:              # pieces arrive as they're generated
        print(text, end="", flush=True)
print()

5Parameters that matter

Three settings change your results, and your bill, more than anything else.

Model. Small models are fast and cheap. Big ones think harder. Start small, and move up only if you need to.

Max tokens. The longest the answer can be. It also caps what one call can cost.

Temperature, from lesson five. Low for facts and code. Higher for ideas.

small: fast, cheaplarge: smarter, costliermax_tokens=200CAPS LENGTH AND COST0.2 · FACTS, CODE0.7 · BALANCED1.0 · IDEAS

6Streaming

Ever noticed chatbots type their answer word by word? That's not an animation. It's streaming.

Without streaming, your app waits until the whole answer is ready, then shows it all at once. Long answers feel slow.

With streaming, pieces arrive as the model writes them. The first words show up almost instantly.

In Python, use messages dot stream, then loop over the text stream and print each piece, without a new line.

Same total time. But it feels much faster, because people start reading straight away. Look at this graph.

7Cheat sheet

  • Send: key · model · messages
  • System · user · assistant
  • Send history each time
  • Start with a small model
  • max_tokens caps cost
  • Stream it

8Quick quiz
