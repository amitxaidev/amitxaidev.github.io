278. First Bad Version

Easy First true

Problem

Versions 1..n are good up to some point and bad after it. Using an isBadVersion(v) API, find the first bad version with as few calls as possible.

This is a short summary in our own words — read the full statement and examples on LeetCode.

Hints

The answers look like F F F T T T. Find the first T.
If mid is bad, the answer is mid or earlier. If good, it's after mid.

Approach

Binary search with lo < hi: bad mid → hi = mid, good mid → lo = mid + 1. When lo == hi, that's the first bad version.

Solution (Java)

/* The isBadVersion API is defined in the parent class VersionControl. */
public class Solution extends VersionControl {
    public int firstBadVersion(int n) {
        int lo = 1, hi = n;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (isBadVersion(mid)) hi = mid;   // mid could be the first bad one
            else lo = mid + 1;
        }
        return lo;
    }
}
Common mistake: (lo + hi) / 2 overflows when n is close to 2^31.
